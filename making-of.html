How to read this page
  • Teacher messages are the requests, typed in plain English. Claude messages are its replies.
  • The grey rows between them are tool calls: Claude reading a file, editing code, running the tests, or taking a screenshot of the page to check its work. Click a row to see exactly what it did and what came back.
  • Some messages were interrupted or sent while Claude was busy; those are marked.
  • What's left out: Claude's private working notes, background instructions from the software, and personal details such as an email address. Very long file contents and outputs are shortened; the full code is on GitHub.
Things to notice (for discussing in class)
  • Plan first. The first request asked only for a plan, and the teacher corrected it twice before any code was written.
  • Asking instead of guessing. Claude asked questions when a rule was ambiguous (what happens to a teacher's beads? does a decline use up time?).
  • Tests. Every feature came with automated tests. Several times the tests themselves were wrong, and Claude fixed the test, not the code. Can you find one?
  • Checking with screenshots. Claude looked at the page after most changes and caught real problems that way: gold necklaces that had become invisible, a page wider than a phone screen.
  • Statistics traps. Look for the discussion of the "Does declining pay off?" chart and survivorship bias: why a chart can look like it proves something when it doesn't.
  • The human stays in charge. The teacher changed direction several times ("ignore my previous comment", "let's hold on that idea"). Claude followed the teacher's judgement.
